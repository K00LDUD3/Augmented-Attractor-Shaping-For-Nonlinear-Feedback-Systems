## [2026-04-11 10:17] Delta 1: The Authority & Scale Imbalance
**Preceding Run UID:** `2026-04-11_02-25-22_60c9b36134` (Run 1)

### Diagnosis
Run 1 performed exceptionally poorly, achieving an evaluation effort 5.5x worse than the PID baseline and an error 21x worse. 
1. **Zero Authority:** `rl_lambda` was too small (0.1). Out of a $U_{max}$ of 250, the RL agent controlled 0.04% of the signal. It could not meaningfully guide the system and merely added output noise.
2. **Reward Scale Imbalance:** `r_dist` routinely hit magnitudes of `-60` and `r_conv` generated `+40,000` spikes over an episode. By contrast, the effort penalty `r_effort` hit absolute maximums of `-0.01` per step. The continuous noise generated by the agent was completely invisible to the optimization process.

### Code Changes
- **Environment (`lorenz_env.py`):** 
  - Substantially altered `_compute_reward()` to mathematically bound all continuous terms (`r_dist`, `r_effort`) to ~`[-1.0, 0.0]`. 
- **Training Config (`train_sac.py`):**
  - `rl_lambda`: `0.1` $\to$ `25.0` (Granted RL agent 10% authority).
  - `reward_effort_coeff`: `0.01` $\to$ `0.1`
  - `reward_convergence_bonus`: `10.0` $\to$ `1.0`

### Expected Behavior
The agent will have sufficient authority (25.0) to significantly perturb trajectories and shift the system to calmer manifolds. The bounded reward components will allow the actor network to actually "see" the effort and GALI gradients.

## [2026-04-12 12:26] Delta 2: The Flat L2 Gradient Mask
**Preceding Run UID:** `2026-04-11_15-55-25_5a35a7224f` (Run 2)

### Diagnosis
Run 2 effort skyrocketed to an average of `41,456` (nearly 9x worse than the PID baseline's `4544`).  While the agent learned to converge, it completely ignored effort minimization and dumped maximum control magnitude (+25.0) continuously.
The root cause was the **squared** $L_2$ norm used for effort penalty calculation: `((u1/250)^2 + (u2/250)^2)`. 
At a steady thrust of 25.0, this squared fraction equals `0.02`. Applying the `0.1` coefficient yielded `-0.002` per step, or `-8.0` over the full 4000-step episode. The Q-network was overwhelmed evaluating the `-8.0` penalty against a `+4000.0` convergence bonus. The derivative (gradient) flattened out immensely near zero, so the agent felt no mathematical pressure to reduce its thrust.

### Code Changes
- **Environment (`lorenz_env.py`):** 
  - Changed `r_effort` from $L_2$ squared norm to an $L_1$ absolute uniform norm: `np.sum(np.abs(u_total)) / (len(u_total) * u_max)`.
  - This perfectly aligns the NN's loss function with the $L_1$ evaluation metric (`total_effort = np.sum(np.abs(u))`) and maintains a steep, linear slope pushing back against effort all the way to zero.
- **Training Config (`train_sac.py`):**
  - `reward_effort_coeff`: `0.1` $\to$ `1.0`.

### Expected Behavior
A maximum, constant RL saturation of `25.0` will now incur an $L_1$ penalty subtracting precisely 10% of the entire `+4000.0` convergence bonus (`-400.0` total). The agent will face massive, linear gradient pressure to cut its interventions down to the absolute minimum necessary to maintain target proximity. Total effort is expected to plummet back to baseline levels or lower.

## [2026-04-13 01:41] Delta 3: Baseline Calibration Error — The 100-IC Stress Test
**Preceding Run UID:** `2026-04-13_04-09-26_2ea6cbee0a` (Run 3)

### Diagnosis
Run 3 looked like effort was too high (eval efforts 22,000–48,000), but we had been comparing against a **single fixed IC** PID baseline (effort=4,544). This was a misleading comparison.

A 100-IC stress test revealed the **true PID baseline** across random initial conditions:

| Metric | Single IC (old) | 100-IC Stress Test (new) |
|:---|:---|:---|
| **Effort** | 4,544 | **25,874 (mean)** |
| **Final Error** | 0.0016 | **0.0354 (mean)** |
| **ITWAE** | 8.61 | **15.25 (mean)** |
| **Conv Step** | 358 | **383 (mean)** |

The single fixed IC happened to be a best-case scenario. Run 3's eval efforts of ~22,000–36,000 were actually **within or near PID baseline range**, not 5-9x worse as believed.

### Code Changes
- **Training Script (`train_sac.py`):**
  - Added `run_pid_baseline_stress_test()` function: runs 100 episodes with zero RL action across random ICs
  - Called automatically before training begins, right after agent/buffer init
  - Logs full statistics (mean, std, median, min, max) for effort, error, ITWAE, reward, convergence step
  - Saves complete per-IC results to `logs/pid_baseline.json` in the experiment directory
  - Configurable via `params["baseline_stress_n"]` (default: 100)

### Expected Behavior
Every future training run will begin with a live, statistically grounded PID baseline from the exact same IC distribution. Eval metrics can now be compared directly against the baseline logged in the same experiment folder — no more single-IC extrapolation errors.

## [2026-04-13 02:16] Delta 4: Fixed Latin Hypercube Sampling (LHS) for Rigorous Comparison
**Preceding Issue:** PID stress test (Delta 3) exposed baseline variation, but training evaluations were still using randomly sampled ICs on the fly. This introduced noise in eval curves (some episodes agent gets "easy" ICs, others "hard"). Further, the PID stress test ICs were independent of the Agent eval ICs.

### Diagnosis
To make the algorithm's performance curve statistically rigorous, the agent should be evaluated on the **exact same** "challenge set" of ICs that the PID baseline was tested on. Random sampling in 6D can leave critical regions untested; Latin Hypercube Sampling (LHS) guarantees a uniform spread across all 6 dimensions. 

### Code Changes
- **Training Script (`train_sac.py`):**
  - Added `generate_lhs_ics()` using `scipy.stats.qmc.LatinHypercube`.
  - At start of `train()`, a master array of $N$ LHS ICs is generated (default $N=250$, based on `max(baseline_stress_n, eval_episodes)`).
  - The master set is serialized to disk (`logs/master_fixed_ics.json`).
  - Baseline stress test runs on the full master set.
  - Periodic evaluations (`evaluate()`) run on a subset (first `eval_episodes`) of that exact same master set.
  - Added multiprocessing (ProcessPoolExecutor) to `run_pid_baseline_stress_test` mapped across local CPU cores (~2.4x speedup, 100 ICs runs in 4m30s).
  - Added CLI overrides for (`--baseline-stress-n`, `--eval-episodes`).

### Expected Behavior
The PID Baseline effort distribution is now the absolute benchmark. Training eval lines will be smooth because the difficulty of the test set is perfectly constant. Any outperformance of the agent against the baseline is mathematically sound because they both face the exact same space-filling set of initial conditions.

## [2026-04-13 10:15] Delta 5: Breaking the Convergence Dominance math
**Preceding Run UID:** `2026-04-12_18-04-59_2ea6cbee0a`

### Diagnosis
Despite achieving great eval errors, effort remained stuck between 18k–30k. Analysis of the reward function revealed a massive mathematical imbalance:
1. The **Convergence Bonus** gives `+1.0` per step (max `+4000` total).
2. The **Effort Penalty** (`reward_effort_coeff=1.0`) on a typical high-effort run (30,000 total effort) only yielded a penalty of about `-60` over the entire episode!
3. The agent would gladly burn 20,000 effort (which only costs it ~40 reward points) to ensure it stays in the convergence zone for just 41 extra steps (`+41` points). The incentive to cut effort sub-15k was nonexistent relative to the massive `+4000` carrot.

### Code Changes
- **Training Config (`train_sac.py`):**
  - `reward_effort_coeff`: `1.0` $\to$ `20.0`.

### Expected Behavior
A run outputting 30,000 total effort will now incur a massive `-1200` penalty to the Q-value, which starts heavily biting into the convergence bonus. Dropping effort from 30k down to the PID baseline of ~25k now saves `200` points. Dropping it further to 10k saves `800` points. The gradients prioritizing effort reduction will be fiercely competitive with the convergence gradients, forcing the RL to discover elegant, low-effort manifolds.

## [2026-04-13 20:55] Delta 6: Chatter Suppression & Sparsity Deadbands
**Preceding Run UID:** `2026-04-13_10-34-41_911800912b`

### Diagnosis
Despite fixing the gradient dominance of the convergence bonus, the RL Hybrid agent heavily underperformed the PID on several validation ICs (e.g. +21.5% Effort, quadrupled tracking error). This occurs because the SAC agent outputs a rapid "buzzing/chattering" signal (`[-25, +25]` switching at 200Hz). High frequency actuation burns massive effort and physically destabilizes the Lorenz attractor due to chaotic phase-shifting, constantly interrupting the stabilizing PID baseline. Neural networks natively struggle to output exactly `0.0`, resulting in a permanent disruptive residual buzz.

### Code Changes
- **Environment (`lorenz_env.py`)**:
  - Implemented state tracking: `self.last_rl_action`
  - Added **Action Derivative Penalty**: penalized `L2(delta_u_rl)` to eliminate actuator chattering.
  - Added **Residual Sparsity Penalty**: penalized `L2(u_rl)` natively.

- **Training Config (`train_sac.py`)**:
  - `reward_sparsity_coeff`: initialized at `0.5`
  - `reward_action_deriv_coeff`: initialized at `1.0`

### Expected Behavior
The heavy L2 quadratic sparsity penalty will suppress the default NN "buzzing", effectively forcing the residual RL algorithm to remain perfectly dormant (`u_rl = 0`) whenever the underlying PID is tracking successfully. The action derivative penalty will enforce smooth curves across the chaotic manifolds, preventing trajectory fracturing and energy bleed. The combined effect will establish a strict "Do No Harm" baseline, strictly preventing the +21% Effort failures observed in prior tests.

## [2026-04-14 13:28] Delta 7: Temporal Decoupling & Network Standardization
**Preceding Run UID:** `2026-04-13_21-21-49_3be4f7c14f`

### Diagnosis
Delta 6 successfully dropped the overall effort by 12.8%, but the tracking error skyrocketed by +131%. The agent became "scared" of the sparsity penalty (which was set at 0.5) and completely turned off, allowing the PID to blindly steer and cause massive overshoot compared to previous runs. Furthermore, structural issues in the architecture exacerbated this:
1. **Timescale Overlap:** Both the PID and the RL agent operated at 500 Hz (`freq_ratio = 1`). This meant the RL agent changed its residual vector before the nonlinear chaotic system had time to respond to the previous perturbation.
2. **Gradient Mismatch:** The tiny residual actions (`u_RL`) were functionally invisible in the SAC Critic compared to the massive 9D state values, resulting in poor policy evaluation capabilities.

### Code Changes
- **Training Config (`train_sac.py`)**:
  - `freq_ratio`: `1` -> `10` (Multi-Timescale Architecture: PID at 500 Hz, RL at 50 Hz).
  - `reward_sparsity_coeff`: `0.5` -> `0.1` (Reduced agent fear).
  - `reward_distance_coeff`: `1.0` -> `5.0` (Boosted incentive to close the error gap).
- **Network Architecture (`sac_agent.py`)**:
  - Injected `nn.LayerNorm(hidden_dim)` into the first layers of both the `Actor` and `Critic[Q1, Q2]` networks to standardize features and maintain Q-gradient sensitivity to micro-actions.

### Expected Behavior
By decoupling the frequencies, the RL agent will now update strictly to guide the "macro" manifold surfing based on the GALI indicators, while the PID handles the 500 Hz micro-stabilization. The LayerNorm will allow the agent to accurately evaluate tiny residual adjustments. Finally, the drastically re-weighted distance and sparsity coefficients will snap the agent back into tracking the target cleanly, aiming for a net drop in both effort AND error.

## [2026-04-16 19:15] Delta 8: Principled Geometric Surfing (caSSM)
**Phase Status:** Prerequisite Manifold Identification (`6d_cassm_batch`)

### Diagnosis
Despite the architectural stabilization in Delta 7 (LayerNorm, Multi-Timescale), the agent still operates in the raw 6D physical space. Analysis reveals that the efficiency is capped at ~22% because the agent is "blind" to the underlying attractor geometry. It treats the 6 coordinates as abstract numbers rather than a manifold. Standard statistical Autoencoders (AE) fail to solve this because they use **orthogonal projections**, which introduce significant state estimation errors in the chaotic, non-normal regimes of the Lorenz system.

### Code Changes
- **Data Generation (`data_gen_18d.py`)**:
  - Shifted from 6D state-only data to **18D Variational Data** (State + 2 Tangent Vectors $w_1, w_2$).
  - These vectors provide the "Fiber" information necessary for principled manifold projection.
- **Manifold Identification (`train_cassm_encoder.py`)**:
  - Implementation of **caSSM (Control-Augmented Spectral Submanifold)**.
  - Replaced statistical MSE bottleneck with **Dynamics-Informed Encoding**.
  - **Tangency Loss**: Forces the latent space coordinates $\xi$ to ignore motion along stable fibers (oblique projection), ensuring the RL agent only "sees" the actionable geometric currents.
- **Reward Shaping (`lorenz_env.py`)**:
  - Transitioned from linear GALI bonus to **Proactive Log-Barrier Penalty**.
  - Formula: $r_{stability} = -\omega \cdot \frac{1}{\log_{10}(\text{GALI}) - \text{GALI}_{min} + \epsilon}$.
  - This creates an "infinite wall" at chaotic boundaries, forcing proactive surfing.

### Expected Behavior
The RL agent will navigate a reduced 4D latent space $(\xi, \dot{\xi})$ where the "rivers" of the attractor are clearly visible. By using fiber-aligned projections, the mapping error during chaotic transients will drop significantly, allowing the agent to catch stable fibers with micro-interventions. This is the primary mechanism to break the -25% efficiency ceiling and target the **-40% to -55% energy reduction** observed in Strategy C literature.

## [2026-04-22 11:55] Delta 8.1: Log-Barrier Safety & Latent Velocity Fixes
**Preceding Issue:** Mathematical inversion bugs in the theoretical Log-Barrier formula.

### Diagnosis
1. **Log-Barrier Explosion:** The formula $r_{stability} = -\omega \cdot \frac{1}{\log_{10}(\text{GALI}) - \text{GALI}_{min} + \epsilon}$ suffers from a critical flaw. If the neural network surrogate predicts an out-of-distribution value (`log_gali < sali_min`), the denominator becomes negative. This inverts the massive penalty into an infinite positive reward, drawing the agent straight into deep chaos.
2. **Latent Velocity ($\dot{\xi}$) Computation:** The caSSM provides position $\xi$, but the agent needs velocity $\dot{\xi}$. While computing the exact Jacobian ($\dot{\xi} = J_{\text{enc}} \cdot \dot{x}$) is theoretically rigorous, it is computationally expensive and highly sensitive to neural network non-smoothness/noise.

### Code Changes
- **Environment (`lorenz_env.py`)**:
  - **Reward Formula Clamping:** Defined `distance_to_chaos = max(log_gali - self.sali_min, 0.0)`. The penalty is now strictly bounded to $-\omega/\epsilon$, ensuring an impenetrable penalty wall.
  - **Velocity Estimation:** Implemented a safe backward finite difference $\dot{\xi}(t) \approx \frac{\xi(t) - \xi(t-1)}{dt}$. Handled environment resets by initializing $\dot{\xi} = 0.0$ to prevent first-step velocity spikes.

### Expected Behavior
The reward landscape is now mathematically protected against inversion bugs, meaning the agent cannot 'hack' the reward function by diving into unmapped regions. The finite-difference velocity calculation provides smooth trajectory tracking without exposing the policy network to encoder gradient noise.
